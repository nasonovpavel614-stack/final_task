# Планировщик задач

Простой веб-планировщик: можно добавлять задачи, смотреть список ближайших дел, редактировать, отмечать выполненными и удалять. Повторяющиеся задачи (каждый день, каждую неделю, раз в месяц и т.д.) переносятся на следующую дату автоматически.

Данные хранятся в SQLite — это обычный файл `scheduler.db` рядом с программой.

## Задания со звёздочкой

В проекте реализовано:

- **Правила повторения `w` и `m`** — задачи по дням недели и по числам месяца (`FullNextDate = true` в тестах)
- **Поиск задач** — по тексту в заголовке/комментарии и по дате (`Search = true` в тестах)
- **Аутентификация по паролю** — через переменную окружения `TODO_PASSWORD` и JWT-токен
- **Docker** — можно собрать образ и запустить в контейнере

## Быстрый старт (локально)

### 1. Установите Go

Нужна версия **1.21 или новее**. Проверка:

```bash
go version
```

### 2. Перейдите в папку проекта

```bash
cd путь/к/final_task
```

### 3. Запустите сервер

```bash
go run .
```

В терминале появится строка вроде:

```
server listening on http://localhost:7540
```

### 4. Откройте в браузере

[http://localhost:7540](http://localhost:7540)

Если пароль не задан — сразу откроется список задач. Если задан (см. ниже) — сначала страница входа: [http://localhost:7540/login.html](http://localhost:7540/login.html)

## Переменные окружения

| Переменная | Зачем | По умолчанию |
|------------|-------|--------------|
| `TODO_PORT` | Порт сервера | `7540` |
| `TODO_DBFILE` | Путь к файлу базы SQLite | `scheduler.db` |
| `TODO_PASSWORD` | Пароль для входа. Если пусто — вход не нужен | не задан |

**Пример с паролем:**

```bash
TODO_PASSWORD=12345 go run .
```

**Пример с другим портом и базой:**

```bash
TODO_PORT=8080 TODO_DBFILE=/tmp/my.db go run .
```

## Запуск тестов

1. В **первом** терминале запустите сервер (с теми же переменными, что будете проверять в тестах):

```bash
go run .
```

2. В **втором** терминале из папки проекта:

```bash
go test ./tests
```

### Настройки в `tests/settings.go`

| Переменная | Значение | Когда включать |
|------------|----------|----------------|
| `Port` | `7540` | Должен совпадать с `TODO_PORT` сервера |
| `DBFile` | `../scheduler.db` | Путь к БД относительно папки `tests` |
| `FullNextDate` | `true` | Если реализованы правила `w` и `m` |
| `Search` | `true` | Если реализован поиск в `/api/tasks` |
| `Token` | `""` | Если включена аутентификация — см. ниже |

### Тесты с паролем (аутентификация)

1. Запустите сервер с паролем:

```bash
TODO_PASSWORD=12345 go run .
```

2. Получите токен (в другом терминале):

```bash
curl -s -X POST http://localhost:7540/api/signin \
  -H "Content-Type: application/json" \
  -d '{"password":"12345"}'
```

3. Скопируйте значение `"token"` из ответа в `tests/settings.go`:

```go
var Token = `eyJhbGciOiJIUzI1NiIs...`
```

4. Запустите тесты снова:

```bash
go test ./tests
```

Без токена при включённом пароле API вернёт ошибку 401.

## Docker

### Сборка образа

Из корня проекта:

```bash
docker build -t todo-planner .
```

### Запуск с базой на вашем компьютере

Файл `scheduler.db` остаётся на хосте, контейнер только подключается к нему:

```bash
docker run --rm -p 7540:7540 \
  -v "$(pwd)/scheduler.db:/app/scheduler.db" \
  -e TODO_DBFILE=/app/scheduler.db \
  todo-planner
```

С паролем:

```bash
docker run --rm -p 7540:7540 \
  -v "$(pwd)/scheduler.db:/app/scheduler.db" \
  -e TODO_DBFILE=/app/scheduler.db \
  -e TODO_PASSWORD=12345 \
  todo-planner
```

Откройте [http://localhost:7540](http://localhost:7540).

## API (основное)

| Метод | Адрес | Назначение |
|-------|-------|------------|
| POST | `/api/signin` | Вход по паролю |
| GET | `/api/tasks` | Список задач |
| POST | `/api/task` | Добавить задачу |
| GET/PUT/DELETE | `/api/task?id=...` | Получить / изменить / удалить |
| POST | `/api/task/done?id=...` | Отметить выполненной |
| GET | `/api/nextdate` | Следующая дата по правилу повторения |

Запросы к задачам (кроме `/api/signin` и `/api/nextdate`) требуют cookie `token`, если задан `TODO_PASSWORD`.
